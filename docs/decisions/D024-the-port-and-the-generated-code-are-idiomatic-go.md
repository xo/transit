# D24. The port and the generated code are idiomatic Go

Status: Decided, amends D1.

Ken decided on 2026-09-29 that the Go of the port is idiomatic Go, and that the
Go that the Go backend writes is idiomatic Go too. The `go-pedantry` skill
and the Go conventions of `AGENTS.md` apply to both.

## What idiomatic means here

1. Names are MixedCaps, with no `ts_` prefix and no underscore. A receiver has
   a short name, the same on every method of its type.
2. A function returns an error value, and does not return a `bool` with an out
   parameter. An error is a constant of the string type `Error`, as in the
   other `xo` repositories, or a type that implements `error`.
3. A function returns several values in place of out parameters.
4. A slice replaces a pointer and a length. A `[]byte` or a `string` replaces
   a C string.
5. The garbage collector replaces the reference counts and the `_delete`
   functions. A type has a `Close` method only when it holds something that
   the collector does not free.
6. A C enum becomes a typed constant with a `String` method.
7. A sequence comes back as an `iter.Seq` (D25).
8. A parse takes a `context.Context` (D25).
9. Every exported identifier has a doc comment that starts with its name.

The runtime uses these C forms, measured on 2026-09-29, and each has a Go
form: 130 macros become functions or constants, 6 unions and 25 bit fields
become structs, fields or typed flags, and 7 `goto` statements become loops.

## What stays from the port

The rules that let a person port an upstream change stay (D1):

1. One C file becomes one Go file, with its functions in the same order.
2. The doc comment of each ported function names the C function.
3. The comments of the C code are ported with the code.
4. The behavior is the same, including the faults of upstream.

A port commit translates the C into idiomatic Go and keeps the behavior. It
does not restructure the code more than idiomatic Go needs. Where an idiom
and the behavior conflict, the behavior wins inside the package, and the
idiom wins at the exported API (D25).

## The generated code

The Go backend writes Go that `gofmt` leaves as it is, with a doc comment on
each exported identifier and the header `// Code generated by transit. DO NOT
EDIT.` It does not write C in Go syntax. D31 holds the form of the tables.
